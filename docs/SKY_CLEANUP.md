# 上側の空の分離（試作）

## GLBから照明を置く前の状態まで一括で作る

元の見た目付きGLBを`scripts/windows/GLBを準備.cmd`へドラッグしてください。コマンドで実行する場合：

```powershell
python -X utf8 run.py prepare "outputs\prague\street_textured.glb"
```

丁寧な空の除去、残った破片の清掃、材質の変更を順に行います。撮影・VLM分析は元の明るい外観で行い、最後に材質を変更します。HPCの`qwen3.8:27b`を使います。元のGLBは変更しません。別のGLBでは屋根や看板を誤選択する可能性があるため、結果の形状を確認してください。今回のプラハで確認した個別の囲みを、別の世界に流用することはありません。

出力フォルダーの`street_relight.blend`を開いてください。画像テクスチャをプリンシプルBSDFのベースカラーへ、そのBSDFをマテリアル出力へ接続します。放射による自発光をなくし、環境光を0、カメラとライトを0で保存します。Rendered表示で暗いところから、Sunや空を追加して確認できます。材質を変更したGLBは`street_relight.glb`です。GLBを別のシーンへ読み込むと、そのシーン側の照明・環境光が適用されます。

既に蓋を除去済みなら、再撮影やAPIの呼び出しなしで材質だけ準備できます：

```powershell
python -X utf8 run.py prepare --cleaned-dir "outputs\sky_cleanup\除去済みの日時フォルダー"
```

`street_clean.blend`は元の明るい見た目を残した確認用、`sky_review.blend`は再処理用です。照明を置く作業には`street_relight.blend`を使います。

この変更は元の画像から照明を逆算して除去する処理ではありません。テクスチャに描き込まれた影や街灯の色は残ります。照明なしでの自発光はなくなり、新しく置いた照明に反応する状態になります。

空除去の途中からやり直す場合は、元のGLBと最初の日時フォルダーを指定します。残った破片の分析先も記録して再利用します：

```powershell
python -X utf8 run.py prepare "元のGLB.glb" --continue-dir "outputs\sky_cleanup\最初の日時フォルダー"
```

## 空を分ける仕組み

`src/streetlab/sky_cleanup.py` は見た目付きGLBをBlenderで5方向から撮影し、KambeHPCの`qwen3.8:27b`に空の位置を選ばせます。点の色を他の視点と比べ、黒い破片・壁に当たる外れ点を除外します。画像上では空からつながる色の領域を広げ、明るさが徐々に変わる空も追従します。小さな内部の穴は埋めて浮いた破片も候補に含めます。
Blenderの3D座標で指定した高さより下は保護します。上側の大きな面はコピー上で細分化し、各面の7か所を画像の空領域と比較します。見える視点で6か所以上一致し、空と判断した視点数が建物と判断した視点数の2倍以上の面だけを除去します。曖昧な境界・見えない面は残します。

空を除いた後の残りで見通しを再計算し、裏側から現れた破片にも同じ判定を繰り返します（追加候補がなくなるまで、最大12回）。画像上の細い切れ目を閉じ、周囲を空に囲まれた穴も空の候補に含めます。さらに、空を除いたことで孤立した小さな上側の塊を調べ、周囲に空が見え、建物側の証拠がないものを除去します。3Dの連結判定では、UVの継ぎ目で重複した頂点を位置で照合するため、普通の建物がテクスチャの境界でばらばらの破片として判定されるのを避けます。
裏側から現れた面は、面全体の空への一致に加えて、面の外周から離した8方向がすべて空である場合にも除去します。別視点の曖昧な判定で小さな浮遊片が残るのを減らす条件です。屋根の輪郭に接していて周囲に建物が見える面には、この例外を使いません。

元のGLB・既存のBlender作業ファイルは変更しません。結果は日本時間の日時フォルダー `outputs/sky_cleanup/日時/` に保存します。実験版なので、赤い候補表示で屋根・壁を巻き込んでいないか確認してください。

## より丁寧な清掃

一括の `run.py prepare` / `run.py build` では、初期の空除去後と追加清掃後にHPCの `qwen3.8:27b` へ除去前後を比較させます。誤って抜けた壁・窓・屋根を `sky_protection_review.json` の保護領域へ追加し、元の撮影チェックポイントから再処理します。追加の保護領域がなくなるまで繰り返し、同じ範囲は画素上の重なりで重複追加を避けます。保護は見えている3D面への対応を確認し、空判定・浮遊片・追加清掃に引き継ぎます。

HPCの指定は前後画像とも照合し、新しく空洞になった画素を含む場合だけ追加の修復として数えます。既に残っている壁や元から空だった領域だけの指定ではループを続けません。保護領域の端や角に触れる三角形も残し、境界に同じ穴を開け直すことを防ぎます。
保護は7つのサンプル点だけに頼らず、三角形の投影範囲と保護画素の重なりも確認します。小さな壁領域がサンプル点の間にある場合も、三角形を保守的に残します。
保護画素から元のメッシュへレイを飛ばし、その画素で実際に見えていた面も記録します。面の中心が別の形状に隠れていても、保護した角が見えていた面は残します。投影方向の奥にある無関係な面を一律に保護する方法は使いません。
Skyの境界の余白は元画像の解像度で決め、PythonとBlenderで同じ画素を使います。欠損・保護可能な領域・HPCの指定領域は、縮小せず元画像上で照合します。縮小した1セルの中で「残っている壁」と「除去されたSky」を取り違えて再修復を数えることを防ぎます。
有効な建物の保護がある場合は、切断・開放境界の平滑化による頂点移動も省きます。面を残した後で輪郭を動かしてしまうことを避け、保護を輪郭の滑らかさより優先します。
追加清掃のHPC提案も複数視点の整合性を確認します。一方向の破片判定だけで、他方向から見えている建物の反対証拠を上書きしません。浮遊片の判定も、強い一方向の証拠だけで反対証拠を無視しない設定です。

画像比較の応答は内容ごとに保存し、同じ画像を再送しません。追加清掃のキャッシュは空除去済みGLBのハッシュで分けるので、修正前の分析を変更後の形状に流用しません。VLMによる誤認がなくなる保証はありませんが、比較画像と保護範囲を確認できる形です。
未完了または不正な応答は別ファイルに保存し、画像からの確認を最大3回再取得します。新しい比較要求は1視点につき最大4個・各4隅の矩形で返すよう指定し、長い輪郭座標による応答切れを抑えます。サーバーの一時エラーはSDKの再試行も使います。中断された過去の応答の末尾を推測して補うことはしません。

```powershell
python -X utf8 run.py sky-cleanup "outputs\prague\street_textured.glb" --quality thorough
```

`thorough`では床と壁への衝突を調べ、通りの前後に立てる地点があれば追加します。最大3地点×5方向を1280×960・32サンプルで撮影します。VLMへの送信は5枚ずつで、各組の分析を保存するため、中断後は完了した組を再送しません。

空を切り分ける上側の大きな面を通常より細かく分けます。切り分けによって新しくできた縁だけを、元の位置からの移動を制限してならします。既存の建物全体を一律に丸くする処理ではありません。頂点の移動上限は高さ範囲の0.15%です。元の生成に含まれる大きな形の崩れや、正解不明の屋根形状を復元する機能ではありません。

## 残った破片・輪郭の追加清掃

```powershell
python -X utf8 run.py sky-polish "outputs\sky_cleanup\空除去済みの日時フォルダー" --analysis-only
```

空を抜いた結果を3.8で再確認し、屋根につながった不自然な塊も候補にします。小さい浮遊片と輪郭の細かい突起は画像の形から判定します。壁の内側にある看板などを守るため、空が含まれない囲みは無視します。通常のPython側では追加でscipyを使います。

新しい日時フォルダーに`*_polish_proposal.png`（赤が追加候補）を保存します。VLMは遠くの屋根や飾りを誤認する場合があるので、候補の画像を確認してください。誤った候補は出力先の`review.json`で視点ごとの囲みを上書きできます。例えば`{"polygons":{"view_07":[]}}`はその視点のVLM候補を使わず、微小な突起の処理だけにします。

確認済みの出力先から適用するとき：

```powershell
python -X utf8 run.py sky-polish "outputs\sky_cleanup\空除去済みの日時フォルダー" --continue-dir "outputs\sky_cleanup\新しく作られた日時_polished"
```

保存済みの分析は再送しません。削る境界の面を追加で細分化し、奥から現れた破片も最大40回まで調べます。元のGLBと前回の結果は保持し、追加で除いた面もBlender内の非表示物体に残します。結果は`street_without_sky.glb`、確認用は`sky_review.blend`です。

画像の形だけによる削除は複数方向の一致を確認します。明示的に囲んだ破片は、実際に見えている方向から3Dの面へ対応付けます。輪郭の処理は上側の開いた縁だけに限定し、UVの継ぎ目を位置で照合します。縁をならす移動上限は高さ範囲の0.8%です。内部の頂点と指定高さより下は動かしません。書き出し前には重複面などを修復し、再検査が通ることを確認します。元から存在するぼけや、生成に失敗した大きな建築形状を復元する処理ではありません。

追加清掃では、最初に見えていた面から奥へ進む距離を高さ範囲の3%までに制限します。破片の裏にある別の建物を、同じ画像の囲みだけで続けて削るのを防ぎます。建物の縁に重なる囲みには誤選択の可能性が残るため、赤い候補画像の確認は必要です。

厚い破片を途中まで削ったことで新しく孤立した小片は、3Dのつながりを調べて追加で除去します。遠くの建築形状などが重なった厚い崩れを処理する場合だけ、確認済みの囲みに対して`review.json`の`artifact_depth_fraction`で視点別の奥行き上限を指定できます。上限を広げると奥の建物も巻き込みやすいため、今回のプラハでは白い崩れを囲んだ`view_07`だけを調整しています。

最後に、書き出し後の各画像で空中に孤立した小片（3画素以上、画面の0.2%以下）を調べます。該当画素から実際に見えている3Dの面を拾い、高さ制限より上のものだけ追加で除去して出力を確認し直します。最大2回で、元の候補も非表示物体として保持します。既存結果の微小片だけを仕上げ直す場合は、同じ再開コマンドに`--specks-only`を付けます。

背後の層まで探した候補がメッシュの0.5%を超える場合は、最初に見えていた小片だけへ戻します。その候補も上限を超える場合は元の形状を保持します。上限を緩めて大量に削除することはなく、判断内容は `report.json` の `final_speck_passes[].bounded_fallbacks` に記録します。建物の保護には、保護画素から実際に見えていた面の記録を使います。

照明を置く作業には`street_relight.blend`を開きます。元の明るい外観は`street_clean.blend`に保持します。どちらも街のメッシュだけを残し、撮影用カメラ・ライト・非表示の除去候補を取り除いて圧縮保存します。保存後に読み直し、カメラとライトが0で街の面数が変わっていないことを確認します。`sky_review.blend`は再処理用の内部チェックポイントとして保持します。GLBには撮影用カメラを含めません。

## 接続設定

`prague/.env`に次の行を追加します。既存のWorld LabsやOpenAIの行は残します。

```dotenv
LLM_KEY=取得したHPCのAPIトークン
LLM_BASE_URL=https://llm.kambehpc.com/v1
LLM_MODEL=qwen3.8:27b
```

`LITELLM_API_KEY`という名前でも使えます。キーの優先順位は、環境変数→pragueの.env→既存のconfig/trellis.local.jsonが指定するHPC用.envです。`--env-file`で指定した場合、別ファイルへのフォールバックはしません。APIキーは出力ファイルに保存しません。HPCのChat Completionsのみを使い、OpenAIの画像生成やWorld Labsの生成は呼びません。

このスクリプトの標準モデルは`qwen3.8:27b`で、実際にHPCでの画像分析を確認済みです。古い共通設定の`LLM_MODEL`が3.5でも、このスクリプトは3.8を使います。変更するときだけ`--model`を指定します。

## 実行

Blender、通常のPython、numpy、Pillow、openaiライブラリが必要です。現在のprague環境には既存処理用として入っています。

```powershell
python -X utf8 run.py sky-cleanup "outputs\prague\street_textured.glb"
```

これは以前のプラハを指定する例です。別のGLBを使う場合はパスを変えます。Blenderは自動検出し、必要なら`--blender "C:\path\to\blender.exe"`で指定できます。
MarbleのOpenCV座標を補正して、BlenderのZ上向きで処理します。すでに自分で向きを直して再保存したGLBには`--source-up gltf`を付けてください。結果のGLBにも補正した向きが反映されます。

APIを呼ばず、撮影位置を確認するだけなら：

```powershell
python -X utf8 run.py sky-cleanup "outputs\prague\street_textured.glb" --prepare-only
```

撮影した`view_00.png`〜`view_04.png`を確認します。最初の4枚は同じ地点から4方向の斜め上、最後の1枚は真上です。VLMが自由に飛行する機能ではありません。初期カメラが壁の中などに入った場合は、`--camera X Y Z`でBlender座標の撮影位置を指定し、新しく実行します。

撮影済みフォルダーから再開する場合：

```powershell
python -X utf8 run.py sky-cleanup "outputs\prague\street_textured.glb" --continue-dir "outputs\sky_cleanup\対象の日時"
```

`analysis.json`があればVLMを再度呼びません。失敗時の自動再送はありません。撮影時のGLBと現在のGLBが同じかハッシュで確認します。
保存済みの分析と指定モデルが異なる場合は停止します。以前の画像を新しいモデルで分析し直す場合は`--continue-dir`の代わりに`--reuse-views "以前の日時フォルダー"`を指定します。前の結果を残し、新しい日時フォルダーで分析します。

VLMの結果はそのままで、後処理を新しいフォルダーへ作り直す場合は`--refine-from "以前の日時フォルダー"`を使います。これは画像・分析結果をコピーし、APIを呼びません。

## 高さ・色の調整

- `--upper-fraction 0.5`：極端な外れ点を除いたメッシュ高さの下半分を保護します。0.7なら下側70%を保護します。
- `--min-z 5`：Blender座標でZ=5より下を保護します。単位はそのGLBのスケールに依存します。
- `--color-tolerance 0.14`：空領域を広げる色の許容距離。急な色の境界では止まり、空の明るさの緩やかな変化には追従します。

これらの条件は新規実行時に指定します。`--continue-dir`では元の条件を再利用します。

## 出力

- `view_00.png`〜`view_04.png`：元の見た目。
- `*_grid.png`：VLMへ送った座標目盛り付き画像。
- `*_mask.png`：空からつながった画像領域（白が空の候補）。
- `analysis.json`：VLMが選んだ空の点と判断理由。
- `filtered_points.json`：色の整合性を確認して実際に使った点。
- `sky_samples.json`：その点に対応する高さ、テクスチャ色。
- `*_overlay.png`：除去候補を赤く表示した比較画像。
- `*_after.png`：候補を隠した画像。マゼンタは形のない背景です。
- `sky_review.blend`：候補を`_SKY_CANDIDATE`という別物体に分け、非表示にした確認用ファイル。
- `street_without_sky.glb`：候補の面を除いたGLBのコピー。
- `report.json`：候補数・条件・限界。
  `revealed_layers`は空の裏から現れた面の除去回数と面数、`floater_details`は孤立した破片の判定根拠です。`visibility_converged`がfalseなら、12回の上限時点でまだ追加候補がありました。

## この処理の限界

上側の建物が空と同じ色でつながっていれば誤選択する可能性があります。これは精密な意味領域分割ではなく、VLMが指定した点と画像の領域拡張・高さ制限を組み合わせる方法です。大きな面は細分化しますが、境界にまたがる面・見えない面・大きな破片は残る場合があります。
保存済みプラハでHPC接続・5方向の分析・分離・GLB書き出しまで確認しました。空の一部は抜けますが、空の端や黒い破片は残るため、世界全体の空を完全に除去する完成版ではありません。
浮遊片の後処理でも、屋根や飾りのような小さな形を空と誤認する可能性は残ります。比較画像と別物体として保存した候補を確認してください。指定した高さより下の破片は保護の対象なので除去しません。

`src/streetlab/sky_cleanup.py`単体の空除去では、元の材質と焼き付いた明暗を保持します。新しく置く太陽光に反応させるには、一括処理で作る`street_relight.blend`または`street_relight.glb`を使ってください。テクスチャ内に描き込まれた明暗は、材質の変更後にも残ります。
