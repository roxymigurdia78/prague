# ヨーロッパ街路・屋外照明のデータセット調査

調査日: 2026-11-04（日本時間）

目的: Blenderで生成したヨーロッパ風の街路について、時間帯との整合性と照明の自然さを評価する研究に使う、大量の実写真を探す。

## 推奨する構成

- **Global Streetscapes**: 撮影条件で検索・抽出するための索引。昼・夜・薄暮、天候などの手動ラベルと自動推定ラベル、既存の分類器がある。
- **Panoramax**: フランス中心に大量のヨーロッパ街路を集める供給元。座標・撮影日時・撮影系列・ライセンス・画像URLを追跡しやすい。
- **OpenStreetView-5M（OSV-5M）**: 大量の画像本体をZIPで入手できる。独自のAPI収集を作る前の選択肢。
- **Dark Zurich / ACDC**: 同じ場所を条件を変えて撮った対応画像で、建物の種類と照明を混同していないか調べる。
- **Aachen Day-Night**: 旧市街・歩行者視点に近い画像で、車載データへの偏りを確認する。

これは研究目的からの提案であり、学習による改善や必要枚数を実証した結果ではない。

## 1. Global Streetscapes

NUS Urban Analytics LabがMapillaryとKartaViewの画像を整理したデータセット。位置、ローカル撮影日時、都市・国・大陸、撮影系列、カメラ情報などに加え、画像の文脈や領域割合などを付加している。

- 時間帯: `day`, `night`, `dawn/dusk`。
- 天候: `clear`, `cloudy`, `rainy`, `snowy`, `foggy`。
- 道・歩道などの撮影対象、正面/側面、パノラマ、品質、反射やグレアも分類する。
- 大規模部分の文脈ラベルは分類モデルの予測。手動ラベル部分と分けて扱う。
- **データだけでなく、これらの条件を予測する学習済みモデルも配布している。** まずQwenと比較する価値がある。ただし実写真での性能をBlender画像での性能とみなしてはいけない。

入手方法: Hugging FaceのCSVを条件で絞り、`uuid`, `source`, `orig_id`を使って公式スクリプトで画像を取得する。Mapillary部分はアクセストークンが必要。元画像が削除されている場合などに全件を再取得できる保証はない。

公式GitHubは全体についてCSV中心の配布と説明する一方、Hugging Faceの`manual_labels/img`には画像アーカイブもある。`manual_labels`ディレクトリは調査時点で23.9GB表示。全1,000万枚の画像がそのまま配布されているという意味ではない。全量の画像取得について、公式Wikiは少なくとも6TBの空き容量と数日程度の取得時間を想定している。

利用条件: データカードはCC BY-SA 4.0を表示。画像の提供元・投稿者・ライセンス情報も保持し、元サービスのアクセス条件と、公開データの再配布条件を分けて確認する。

## 2. Panoramax

IGNとOpenStreetMap Franceが共同開発した、写真を複数のサーバー（インスタンス）で公開する仕組み。ヨーロッパ、とくにフランスの道路・街路・建物を大量に収集する候補として強い。

IGNの2026-10-19記事では約1.1億写真とされる。これは常時変動するサービスの規模であり、旧市街・夕方・良質な街路写真だけが1.1億枚あるという意味ではない。

メタデータの週次GeoParquet書き出しには、座標、撮影日時`datetime`、アップロード日時`created`、撮影系列`collection`、撮影方向、画像asset、投稿者、ライセンスがある。地域を絞ったAPI検索のほか、大量の索引を先に絞り込む収集方法が公式に用意されている。

利用条件はインスタンスごとに異なる。調査時点の公式一覧ではIGNがEtalab 2.0、OSM-FRがCC BY-SA 4.0。個別レコードのライセンスも保存する。

**実際の取得確認**: パリ中心部の小範囲を`limit=1`で検索し、HTTP 200、画像1件の緯度経度・撮影日時・ライセンス・HD/SD/サムネイルURLを取得できた。ログインやAPIキーなしでこの公開検索が応答した。画像本体の一括取得は実施していない。

確認したサンプル:

```json
{
  "id": "a09fd242-102e-42cb-80e8-89ba31d684b2",
  "longitude": 2.340144612,
  "latitude": 48.855196946,
  "datetime": "2025-05-05T06:16:57.821000+00:00",
  "license": "etalab-2.0"
}
```

注意: 撮影日時は投稿されたメタデータであり、正確さが保証された照明計測値ではない。APIの集約期間にも将来年の値が含まれていたため、異常な年、タイムゾーン、連続系列内の時刻の飛びを検査する。夜・薄暮の件数分布は未集計。

- [公式インスタンス一覧・ライセンス](https://explore.panoramax.fr/en/instances)

## 3. OpenStreetView-5M（OSV-5M）

Mapillary由来の街路画像をまとめた研究データ。約510万枚の画像本体をHugging FaceのZIPで取得できる点が実用的。全体は世界のデータなので、国・座標で欧州部分を抽出する。

- 論文の内訳: 学習4,894,685枚、テスト210,122枚。
- 論文による画像サイズ: 高さ512px、平均幅792±127px。
- 完全版のメタデータには緯度・経度、国・都市、`sequence`, `captured_at`, 投稿者情報が含まれる。
- 既定の簡易データローダーは撮影日時を返さないため、完全版メタデータまたは元のCSVを使う。欄があることと各レコードの値が正確・完全であることは別。
- 元の目的は地理的位置推定。照明の自然さに関する人手の採点や、天候の正解ラベルは、この配布説明からは確認できない。

容量: Hugging Faceの表示は全リポジトリ259GB。展開時の空き容量も必要。

利用条件: 公式データカードはCC BY-SA 4.0。

**実際の取得確認**: `images/train/00.zip`へのHEADリクエストはHTTP 200、Content-Length 2,521,780,707 bytes（約2.52GB）。これは1巻のサイズであり、全体のサイズではない。ZIP本体の保存・展開は行っていない。

一次資料:

- [公式配布・ダウンロード例](https://huggingface.co/datasets/osv5m/osv5m)
- [公式ローダーとメタデータ項目](https://huggingface.co/datasets/osv5m/osv5m/blob/main/osv5m.py)
- [CVPR 2024論文](https://openaccess.thecvf.com/content/CVPR2024/papers/Astruc_OpenStreetView-5M_The_Many_Roads_to_Global_Visual_Geolocation_CVPR_2024_paper.pdf)

## 4. MSLS

約160万枚、30都市の街路画像。季節、昼夜、経年差にわたる場所認識のデータで、ヨーロッパの複数都市も含む。

公式READMEの構造:

- `raw.csv`: `lon`, `lat`, 撮影方向`ca`, `captured_at`, パノラマ情報。
- `seq_info.csv`: `sequence_id`, `frame_number`。
- `postprocessed.csv`: 昼夜`night`、視線方向など。
- `images_vol_X.zip`: 画像を6巻に分割。

撮影時刻と場所があり、昼夜を扱う研究の基盤として有力。ただし、近い場所を再訪した画像であり、全てが厳密な同一視点の照明ペアではない。

配布ページは調査環境では「Not Logged In」を表示。ログイン後の画像データ利用条件・実容量は未確認。GitHubリポジトリのMITライセンスはコードの説明であり、それを画像データに適用してはいけない。

- [公式配布入口](https://www.mapillary.com/dataset/places)

## 5. Dark Zurich

同じ道路を昼から薄暮、夜にかけて繰り返し走行したデータ。GPSによる対応付けがあり、同じ街の見た目が時間帯でどう変化するかを調べられる。全8,779枚。

学習部分は昼3,041枚、薄暮2,920枚、夜2,416枚で、別途夜間の評価画像等が含まれる。撮影車両や歩行者、視点は変わるため、単純な画素差を「照明だけの差」とみなさない。撮影した時計時刻の全レコード公開状況は未確認。昼・薄暮・夜という条件分類と正確な時計時刻を区別する。

**実際の取得確認**: 著者のGitHubから案内される匿名化学習用ZIPにHEADし、HTTP 200、16,626,364,251 bytes（約16.63GB）を確認。全データセットの容量ではない。データの保存・アーカイブ内の利用条件の確認は未実施。コードのライセンスと画像の利用条件は分ける。

## 7. NightOwls

欧州3か国で撮影された約279,000フレーム、40系列。夜・明け方、四季・天候の変化を含み、解像度は1024×640。

## 8. Cityscapes

欧州50都市。中心となる選定画像は精密ラベル5,000枚＋粗いラベル20,000枚。周辺の30フレーム動画と右ステレオ画像も提供するため、総フレーム数は25,000枚より多い。

公式条件は昼間・良好〜中程度の天候。前の説明にあった「晴れた昼間だけ」は強すぎる表現。ただし夕方・夜の研究の主材料にはしにくい。

利用には無料登録が必要で、現行規約には科学的関心を持つ機関への所属や利用目的の範囲の条件がある。今回の照明研究が条件に合うかは、登録時に具体的な研究目的と照合する。

## 9. Aachen Day-Night v1.1

## 10. SkyFinder

## その他の候補と、今回の優先順位を下げた理由

- **Mapillary全体**: 公式紹介は24億枚超。API収集の大元として重要だが、目的の条件を絞るにはGlobal StreetscapesやMSLSなどの整理済みデータが便利。画像はCC BY-SAと説明され、APIの利用にはサービス側のアクセス条件も関わる。[公式紹介](https://help.mapillary.com/hc/en-us/articles/115001770269-An-Introduction-to-Mapillary)、[画像ライセンス](https://help.mapillary.com/hc/en-us/articles/115001770409-CC-BY-SA-license-for-open-data)
- **AMOS**: 現在の公式案内は数億枚・約55TBの大規模かつ未整理なデータで、アクセスには申請が必要としている。古い記事の巨大な枚数だけを見て「すぐ一括取得できる」とは言えない。1か月の実験なら公式自身が案内するSkyFinderから試す。[現行の公式案内](https://mvrl.cse.wustl.edu/datasets/amos/)
- **Transient Attributes**: 論文では101カメラ、8,571画像、40の知覚的属性。照明・天候のラベルとして関連性は高いが、元プロジェクトページは今回タイムアウトし、現行の画像取得先と条件を確認できなかった。今すぐ大量入手する本命にはしない。[著者の論文](https://jrenzhile.com/publications/siggraph2014/TransientAttributes.pdf)
- **Laval Outdoor HDR**: 実照明のHDR環境マップを使う別方向の候補。照明をJPEGの見た目以上に物理的に扱いたい場合に重要。公式研究ページのデータ案内は確認したが、配布サイトの取得は失敗し、利用条件とダウンロード可否の全文確認は未了。[公式研究ページ](https://lvsn.github.io/deepskymodel/)
- **Oxford RobotCar**: 公式サイトに2026-10-22付で、追って通知するまでデータセットを取り下げるとの告知。新規入手の本命から除外。RobotCar由来の別配布物が今も使えるかは、それぞれ独立に確認する必要がある。[現行の公式告知](https://robotcar-dataset.robots.ox.ac.uk/)
- **4Seasons**: 著者GitHubは存在するが、旧公式ドメインの現行ページに研究と無関係なカジノ関連文言が多数混在していた。今回、安定した正規の画像入手経路を確認できなかったので本命から除外。これはページ内容の観察であり、原因を特定したものではない。[著者GitHub](https://github.com/pmwenzel/4seasons-dataset)

## データを研究に使うときの設計

以下は調査結果を踏まえた研究上の提案。

### 教師信号を分ける

1. **時間帯や太陽条件**: 信頼できる撮影日時と緯度経度から太陽高度・方位を計算し、写真との対応を学ばせる。曇りや建物の遮蔽があると、画像だけでは高度を一意に逆算できない。`日中/薄暮/夜`等の粗い条件から始める。
2. **自然さ**: 実写真には通常「この3Dの照明設定のどちらが自然か」という教師信号はない。実写真を参照に使い、Blender側の比較画像に人の判断を付ける等の追加設計が必要。単なる実写/CG分類器は、テクスチャやノイズを判別するだけでも高得点になりうる。

写真1枚からの「18時ちょうど」推定を中心課題にしない。同じ18時でも日付・緯度経度で太陽位置が異なり、同じ太陽高度でも午前と午後の可能性がある。撮影方向、天候、露出やホワイトバランスも影響する。評価対象を「指定した場所・日付・時刻の照明として矛盾しないか」に置く。

太陽位置の計算は、時刻のタイムゾーンを明確にして行う。参考: [pvlibの公式太陽位置API](https://pvlib-python.readthedocs.io/en/stable/reference/generated/pvlib.solarposition.get_solarposition.html)。

### 残すメタデータ

`dataset/source`, 元画像ID、画像URL、投稿者、ライセンス、撮影日時の原値、UTC日時、タイムゾーン、緯度経度、撮影方向、撮影系列、場所のグループ、条件ラベル、ラベルの由来（人手/計算/モデル予測）、品質状態、学習/検証/評価の分割を保持する。

- `created`（アップロード）を`datetime`/`captured_at`（撮影）と混同しない。
- 時刻がない、タイムゾーンが不明、画像の昼夜と日時が明確に矛盾するものを正確な時刻の教師にしない。
- Global Streetscapesの自動ラベルは収集時の絞り込みに便利だが、独立した人手の正解とは分ける。
- 同一の画像がOSV-5MとGlobal Streetscapesの両方に入っている可能性を考え、元IDや画像ハッシュで照合する。
- 連続フレームや同じ建物の別時刻を、画像単位のランダム分割で学習側と評価側にばらまかない。撮影系列・場所・できれば都市をまとめて分割する。
- パノラマの複数切り出しも同じグループにする。1枚のパノラマから作る複数視点は、新しい独立した撮影事例とは数えない。
- 人工的に色や明るさを変えた画像は、実際にその時刻に撮影された写真とは区別する。

### 1か月での収集・評価案

1. 最初にGlobal Streetscapesの手動ラベル部分、Dark Zurich、Aachenなどで既存Qwenと公開分類器を比較する。評価用には人が確認した画像を確保する。
2. 大量画像の母体はOSV-5Mの欧州部分、またはPanoramaxの対象地域とする。Global Streetscapesは天候・時間帯を絞る索引として使う。元IDで重複を落とす。
3. 初回は**独立性の高い3万〜10万画像を目標**にし、都市・系列・時間帯・天候の偏りと取得成功率を測る。これは計画上の目標であり、条件を満たす件数を確認した数字ではない。
4. Dark Zurichの昼/薄暮/夜、ACDCの天候、NightOwlsの夜を使い、不足した条件を補う。ただし条件ごとにデータセットが完全に分かれると、カメラの違いを時間帯の手掛かりに学習してしまう。複数の供給元で条件を揃える。
5. データと計算時間に余裕があれば数十万〜100万画像に拡張する。実写真の学習で改善したか、Blenderの未使用シーンで人の順位と一致するかを別々に測る。

データ量別の容量は解像度・形式で大きく変わる。仮に1枚100〜500KBにそろえた場合、10万枚で約10〜50GB、100万枚で約100〜500GBになるという単純計算。公式アーカイブの実容量とは別。
