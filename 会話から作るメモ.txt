会話JSONから世界を作るメモ（2026-11-10）

【普段はこれだけ】
1. このフォルダの .env を開き、WORLD_LABS_API_KEY を使いたいキーに変えて保存する。
2. このフォルダの「会話.json」をメモ帳で開き、content の日本語を書き換えて保存する。
3. 「会話から世界を作る.cmd」をダブルクリックする。

PowerShellから実行しても同じ：
cd C:\Users\Astra\Desktop\prague
.\.venv\Scripts\python.exe -X utf8 run.py conversation-build

Windows上の会話ファイルを読む。Macから送る操作と受信サーバーの起動は省ける。
HPCの接続設定は既存のものを使う。英語プロンプトを自分で書く必要はない。
この会話ファイルから初めて通常実行する場合は、新しいWorldを作る。
現在のウィーン・ドイツの一括処理は別ジョブ。既存2件の再開方法は実行メモ.txtの保存先指定を使う。

【会話.jsonの書き方】
いま入っている例：
{
  "messages": [
    {"role": "user", "content": "ドイツのローテンブルク風の街を作りたい。石畳の細い通りに、古い木組みの家が並んでいる感じ。"},
    {"role": "user", "content": "季節は夏、時間帯は昼にして。"}
  ]
}

role の user は「自分の発言」という意味。自分の発言だけでもよい。
messages、role、content、引用符などの形式は残し、content の文章を変更する。
「国名・地名」「どんな街か」「季節」「時間帯」を書く。
例：チェコのプラハ、石畳と古い建物、秋、夕方。
例：オーストリアのウィーン、古い街並み、夏、昼。
日時を具体的にしたい場合は、文章に年・月日・現地時刻も書く。

会話は上から時系列。後から「やっぱりウィーンにして」などと訂正した内容をHPCが優先する。
assistant の発言を含むMac側の会話JSONも、ファイルを指定すれば同じ入口で使える。
情報が足りなければ不足項目を表示して止まるので、会話に追記して実行する。
JSONが書き間違っている場合も、APIを呼ぶ前に形式エラーを表示する。

【コマンド1回で自動的に行うこと】
会話JSONを読む
→ HPCで会話全体から最終的な希望を抽出し、Marble用の英語プロンプトを作る
→ 地名から緯度・経度・標高・タイムゾーンを取得し、季節・時間帯から日時を選ぶ
→ 選ばれた地点・日時の気象・CAMS大気データを取得
→ Marbleで世界を生成し、HQのテクスチャ付きGLBを取得
→ 蓋・破片の除去とHPC確認、Principled BSDF化、自発光・環境光ゼロ
→ 窓・街灯・ランタンの3D検出、位置と範囲をJSON・マーカーへ保存
→ 地点・日時・標高・大気を使った太陽と空を初期Blenderへ設定
→ カメラ位置の土台も保存

この順番をPythonプログラムが実行する。GPT画面で毎回手順を頼む必要はない。
Marbleへは場所の説明＋固定の均一な曇天の指定を送り、日時の太陽は後段のBlenderへ渡す。
HPCが選んだ地点・日時を、そのまま後続へ引き継ぐ。

【完成したら開くもの】
実行画面に「大気を反映した初期状態」として表示される street_initial.blend を開く。
太陽はSkyテクスチャで表現する。Sunライトオブジェクトは置かない。
窓などのマーカーは入るが、窓を発光させたり、街灯のライトを置いたりはしない。
保存状態のカメラ・ライトオブジェクトは0。

照明ゼロの street_relight.blend / .glb は別に残る。これは照明を置くための暗い素材。
元テクスチャに描かれている明暗は残る。
窓・器具の位置は inventory.json、撮影位置の土台は camera.json。
成果物のパス一覧は、その回の result.json。

保存先の例：
outputs\conversations\会話ごとのID\world_prompt.txt  … HPCが作った英語プロンプト
outputs\builds\日時_conversation_ID\                  … 初期Blenderと全体の記録
保存先は毎回画面に表示される。過去の世界は削除しない。

【初期設定では本撮影をしない】
清掃・検出用の内部画像は作る。本撮影の写真セット、街灯の照明配置、機械学習の実行はしない。
後で同じ会話の世界へ道路探索と本撮影も追加したい場合：
.\.venv\Scripts\python.exe -X utf8 run.py conversation-build --with-capture

【途中で止まったとき】
会話を書き換えず、同じ conversation-build コマンドをもう一度実行する。
「続きから」と会話に追記する必要はない。
同じ会話なら保存済みの処理を再利用し、完了していれば結果を再表示する。重複生成しない。
会話の文章を変えた場合は、別の世界として新しい処理を作る。
キーを変えただけでは、同じ会話の完了済み世界を生成し直さない。
GLB取得前に停止した世界を再開するときは、その世界を生成したWorldキーを使う。
正常な元GLBがローカルにあれば、キー変更後でも後処理から再開できる。
同じ会話を二重起動しない。PCスリープ中はPC上の処理が進まない。

【プロンプトだけ先に見たい場合】
.\.venv\Scripts\python.exe -X utf8 run.py conversation-build --prompt-only
HPCでプロンプト・地点・日時まで作る。World Labsで世界は生成しない。
HPCのAPIは使うが、World Labsの生成クレジットは使わない。
確認後に、オプションなしの conversation-build を実行すれば続きへ進む。

JSONの形式だけ確認したい場合（APIなし）：
.\.venv\Scripts\python.exe -X utf8 run.py conversation-build --dry-run

別の会話JSONを使う場合：
.\.venv\Scripts\python.exe -X utf8 run.py conversation-build "C:\会話の保存先\別の会話.json"
JSONを「会話から世界を作る.cmd」へドラッグしても指定できる。

【料金・大気の参照年】
標準の marble-1.1 は世界生成1,580＋HQ GLB作成3,500＝5,080クレジット。
7,000からなら1,920が残る計算。HPCの利用はWorld Labsとは別。
残高照会：
.\.venv\Scripts\python.exe -X utf8 run.py credits

大気・気象の参照年は config\build_world.json の2025年。実行日のリアルタイム天気ではない。
生成中にキーを変更しても、そのプロセスのWorld生成・GLB取得は起動時のキーを使い続ける。

従来の英語プロンプト直接入力は「世界を作る.cmd」と config\world_prompt.txt。
日本語の会話から始める場合は、このメモの「会話から世界を作る.cmd」を使う。
